SIP Project: T.A.Q.

Technical, Analytical, Quantitative — an AI-assisted trading journal analyzer.

Project Description

This project will create a website that allows users to share their trading journal into a website that will conduct a quantitative analyses and return an output file that will highlight patterns, data and other behaviors uncovered by observing the trading journal.

Problem Statement

Trading platforms offer surface level analytics for retail traders. While this information serves casual users, it leaves serious traders without the depth needed to actually improve. As a result, traders are left trying to identify behavioral patterns and recurring mistakes that leave Traders questioning the viability of their abilities and strategies. TAQ will address this by applying data analytics and machine learning to the data traders already generate to identify blind spots and statistical weaknesses that often get overlooked. This will give retail traders an institutional level assessment.

Project Scope

  • Journal upload and parsing from any trading platform
  • Automated performance metrics — profit factor, expectancy, drawdown, payoff ratio, streaks, risk-adjusted return
  • AI-generated written performance review

Target Market

  • Retail traders
  • Algorithmic and systematic traders
  • Proprietary trading firm traders and evaluation candidates
  • Trading educators and mentors
  • Anyone keeping a manual trade journal

Innovation Claim

Innovation Claim

TAQ brings institutional-grade analytics and machine learning to the retail trader, giving every trader access to their own quantitative team.

Prototype / Proof of Concept

The prototype lets a trader upload a CSV, computes the full metric suite, renders an equity curve, and returns a written AI assessment with an edge verdict. It is currently in development; the planned build phases are below.

Technical Field

This project involves the technical fields of Machine Learning, Data Science, Artificial Intelligence and Natural Language Processing.

Background Information

Many individuals pursue trading and investing to bolster, supplant or create a means of financial provision. However, what often goes overlooked is the difficulty in understanding why the same trade(s) and conditions have different results. Trading journals often reflect the “What” of what happened. They never help identify the “Why”. Generic information provided by trading journal programs leaves many constantly questioning. Feedback from professional traders has proven that there is a desire to have a TAQ platform that can help uncover the true edge of a strategy.

Prior Art (Research)

Prior Art Disclaimer: Prior art exists in the realm of trade journaling services that connects a user to various brokers. The services below are most relevant to TAQ, and are acknowledged as prior art.

TraderSync is an AI-powered trading journal that connects to over 900 brokers and acts as a “one stop shop” for data analytics and warehousing. It is a paid service and describes “what” happened as opposed to using statistics and data analysis to describe the “why”. TAQ will provide the user information by applying statistical inference, machine learning and data analysis principles to uncover the “why” that many retail traders cannot receive by journaling services.

Usage Scenario

An individual begins testing a new strategy. This strategy focuses on finding an entry point on or around key daily levels. Their execution occurs on the 5 minute timeframe and utilizes 3 indicators. However, their paid trading journal service only shows “Monday is your least profitable day”, in addition to showing typical trading journal information (time in trade, win rate, Sharpe Ratio, etc). This individual can instead use TAQ and get a plethora of information. Utilizing Machine Learning, TAQ helps this individual identify which features are most dependent on successful trades. It can help identify via a correlation heatmap which time and instrument lead to the most profitable trades. TAQ also includes various (and often overlooked) statistics that include a natural language explanation of these statistics. After looking at the assessment of their trade log from TAQ, the user now truly understands the scope of their strategy and how to make each trade as statistically probable to make money. The user will be able to get an analysis of Tilt detection, position size discipline score, drawdown analysis with simulation in addition to many more statistics that are not an option with their paid journal services.

SIP Brief — Part 2

Evaluation criteria, goals and tasks, and the design prototype.

Evaluation Criteria

  • Does the system accept and parse trade journals in CSV, Excel, HTML and MetaTrader 5 formats?
  • Does the system validate uploads and reject unsupported documents?
  • Does the system normalize journals from different platforms into a single consistent structure?
  • Does the system compute core performance metrics?
  • Does the system compute behavioral metrics?
  • Does the machine learning model identify trade features?
  • Does the language model generate a written, plain language review of the computed statistics?
  • Does the system provide a downloadable report to the user?
  • Does the system return the same results on repeated submissions?

Goals and Tasks Associated with the Project

Objective 1 — Build the intake and parsing layer.

  • Build a drag/drop intake box on the website that takes in multiple file types
  • Build a Python backend that parses the file(s)

Objective 2 — Build the metrics and analytics engine.

  • Implement the performance metrics
  • Implement the behavioral metrics
  • Generate equity curve and drawdown simulations
  • Create correlation and feature analyses

Objective 3 — Develop the Machine Learning model.

  • Engineer features from journal
  • Train and validate a classifier

Objective 4 — Integrate the natural language layer.

  • Create localized language model (LLM)
  • Design process that converts statistics into written assessment
  • Generate assessment
  • Create visualizations to accompany assessment

Objective 5 — Deploy the prototype and integrate with website.

  • Host Python backend

Description of Design Prototype

The prototype for this is a web application made using GitHub. The front end (what the user sees) is the HTML page that allows a drag and drop of submission files. Once uploaded, the file then gets sent and parsed to the back end which is a Python file. This Python file will use various libraries that will be able to conduct the data science and machine learning functions. The file, after getting parsed and analyzed, will then be returned to the user as a downloadable report.
